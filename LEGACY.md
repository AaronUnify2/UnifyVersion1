# Legacy files

These are superseded but kept for reference. Nothing here feeds the live site
any more — editing them changes nothing.

## Superseded by Process Hub

| File | Was | Now |
|---|---|---|
| `FAQ-Editor.html` | The FAQ content editor | [`processhub/`](processhub/) — edits FAQ content, knowledge base articles and process maps together |
| `FAQ.json` | The published FAQ content | `processhub/exports/FAQ.json`, generated by Process Hub |
| `CustomerService.html` | Call flowcharts, hand-written Mermaid | Imported into Process Hub as 112 processes and 37 articles |
| `WorkAdministration.html` | The process mapper | Its data model and step cards live on in Process Hub |

`FAQ-Editor.html` carries a banner saying so, because the two look alike and
it would be easy to spend an evening editing the wrong one.

## What reads what now

```
processhub/index.html   edits everything, exports the files below
        ↓
processhub/data/        processes.json · library.json · variables.json
processhub/exports/     FAQ.json  ← the single source for published FAQ content
        ↓
FAQ.html                the public page, reads processhub/exports/FAQ.json
```

The `FAQ.json` at the repository root is the frozen pre-Process-Hub copy. It is
kept so the import can be re-checked against its original, which is exactly
what `processhub/tools/export-faq.py --check FAQ.json` does.

## Earlier drafts

Numbered variants — `FAQ1.json`, `FAQdemo.html`, `CustomerService1.html`,
`WorkAdministration2.html`, `factory-mapper-*.html` and so on — are working
